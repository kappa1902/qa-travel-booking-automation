# План автоматизации текестирования сервиса покупки туров

## 1. Перечень атоматизируемых сценариев

### Исходные данныет
* **Тестовая карта APPROVED**: '4444 4444 4444 4441` (статус `APPROVED`)
* **Тестовая карта DECLINED**: `4444 4444 4444 4442` (статус `DECLINED`)
* **Срок действия**: месяц — текущий, год — текущий + 1
* **Владелец**: `IVAN IVANOV`
* **CVC/CVV**: `123`

---

### UI-тесты

#### Позитивные сценарии
1. **Успешная оплата по карте (обычная оплата)**
    * Нажать «Купить»
    * Ввести валидные данные карты `APPROVED`.
    * Нажать «Продолжить».
    * **Ожидаемый результат**: Всплывающее уведомление «Операция одобрена Банком», в БД создана запись со статусом `APPROVED`.

2. **Успешная покупка в кредит**
    *Нажать «Купить в кредит»
    *Ввести валидные данные карты 'APPROVED'.
    *Нажать «Продолжить»
    * **Ожидаемый результат**: Уведомление «Операция одобрена Банком», в БД запись со статусом `APPROVED`.

3. **Отказ в оплате по карте DECLINED**
   * Ввести данные карты `DECLINED` для обычной оплаты или кредита.
   * **Ожидаемый результат**: Уведомление «Ошибка! Банк отказал в проведении операции», в БД запись со статусом `DECLINED`.

#### Негативные сценарии (Валидация полей)
1. **Пустая форма**: Оставить все поля пустыми $\rightarrow$ под каждым полем подсказка «Неверный формат» / «Поле обязательно для заполнения».
2. **Невалидный номер карты**: Ввести 15 цифр (`4444 4444 4444 444`) $\rightarrow$ ошибка «Неверный формат».
3. **Истёкший месяц**: Ввести прошлый месяц текущего года $\rightarrow$ ошибка «Неверно указан срок действия карты».
4. **Истёкший год**: Ввести прошлый год $\rightarrow$ ошибка «Истёк срок действия карты».
5. **Владелец на кириллице**: Ввести `ИВАН ИВАНОВ` $\rightarrow$ ошибка «Неверный формат».
6. **Неполный CVC/CVV**: Ввести 2 цифры (`12`) $\rightarrow$ ошибка «Неверный формат».

---

### API-тесты
1. **POST `/api/v1/pay` с валидной картой APPROVED** $\rightarrow$ Статус ответа `200 OK`, `status: APPROVED`.
2. **POST `/api/v1/pay` с валидной картой DECLINED** $\rightarrow$ Статус ответа `200 OK`, `status: DECLINED`.
3. **POST `/api/v1/credit` с валидной картой APPROVED** $\rightarrow$ Статус ответа `200 OK`, `status: APPROVED`.
4. **POST `/api/v1/credit` с валидной картой DECLINED** $\rightarrow$ Статус ответа `200 OK`, `status: DECLINED`.
5. **POST с пустым телом запроса** $\rightarrow$ Статус ответа `400 Bad Request` или `500 Internal Server Error`.

## 2. Используемые инструменты
* **Python**: Язык программирования для написания автотестов.
* **Pytest / Behave**: Фреймворки для запуска тестов и реализации BDD-подхода.
* **Selenium WebDriver / Playwright**: Для автоматизации действий пользователя в браузере.
* **Requests**: Для отправки HTTP-запросов при API-тестировании.
* **PyMySQL / SQLAlchemy**: Для прямого подключения к базе данных MySQL и проверки записей в таблицах.
* **Allure Framework**: Для генерации наглядных графических отчетов прохождения тестов.

---

## 3. Возможные риски
* **Отсутствие `data-test-id`**: Локаторы UI-элементов могут опираться на динамические CSS-классы и тексты, что повышает хрупкость UI-тестов.
* **Нестабильность симулятора**: Ошибки или задержки в работе `gate-simulator` могут вызывать падение тестов по тайм-ауту.
* **Рассинхронизация с БД**: Возможное несовпадение сохранённых данных в СУБД с ответами API/UI.
